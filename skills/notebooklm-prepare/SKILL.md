Note記事やYouTube動画構成を入力として、NotebookLMにコピペするだけでスライドが生成できるプロンプトを出力する。

NotebookLMのスライド生成は1回15枚が上限だが、このスキルが出力するプロンプトはその制限を突破できる。デザイン情報をパラメータ内に直接書き込むことで、何回生成してもデザインが統一される仕組み。

## ワークフロー

### Step 1: 入力ソースを特定する

以下のいずれかを入力として使う:

- `note_article_ren_style.md`（Note記事）
- `note_article.md`（Note記事）
- `yt_video_structure.md`（YouTube動画構成）
- ユーザーが指定したMarkdownファイル
- ユーザーが直接貼り付けたテキスト

入力が指定されていなければ、カレントディレクトリで上記ファイルを探す。

### Step 2: モードを判定する

2つのモードがある。ユーザーの指示から判定する。

**モードA（デフォルト）: 記事ベースで構成案を提示**
- 発表時間が指定されていない場合
- 記事の内容からスライド構成案を作り、枚数と所要時間の選択肢を提示する
- ユーザーが選んでから生成に進む

**モードB: 発表時間ベースで逆算**
- 「30分で」「15分のプレゼン用に」など発表時間が指定されている場合
- 1枚あたり1分として枚数を逆算し、その枚数に収まる構成を作る

### Step 3: スライド構成案を作成する

入力ソースを読み込み、以下の方針でスライド構成案を作成する。

構成の原則:
- 1スライド = 1メッセージ。複数の概念を1枚に詰め込まない
- 見出し（H2）ごとにセクション分け
- 小見出し（H3）や重要な段落ごとに1スライド
- 冒頭にタイトルスライド、末尾にまとめスライドを入れる
- 箇条書きが4項目以上ある場合は複数スライドに分ける
- 具体例やBefore/Afterは専用スライドにする
- スライドタイトルはマーケティング的に次が見たくなる表現にする（誇張はしない）

**モードAの場合:**
まず各スライドのタイトルを箇条書きで一覧化し、以下の選択肢を提示する:

> この記事から以下の構成が作れます:
> - コンパクト版: 〇枚（約〇分）
> - 標準版: 〇枚（約〇分）
> - 詳細版: 〇枚（約〇分）
> どれにしますか？

**モードBの場合:**
指定された発表時間から枚数を算出し、その枚数に収まるように構成を調整する。

ユーザーの選択を待ってからStep 4に進む。

### Step 4: デザイン指示を決める

ユーザーにデザインの方向性を確認する。指定がなければ以下のデフォルトを提案:

- デザインスタイル: 堅実でクリーンな企業スタイル（信頼感・誠実さ重視）
- 配色: 背景#ffffff、文字#0ea5e9、強調#e9520e、補助#7dd3fc
- レイアウト: グリッドベースの整然とした配置
- その他: キャラクター画像がある場合は各スライドに効果的に配置。スライドの内容に合わせて説明役・案内役・リアクション役など文脈に応じた役割で登場させる。画像がない場合は省略可。フォント名・カラーコードをスライドに書かない、日本語ベース、配布資料としても使える読みやすさ、非エンジニアにも親しみやすいデザイン

ユーザーが独自のデザイン指示を持っている場合（別ファイルや口頭指示）はそちらを優先する。

### Step 5: NotebookLM用プロンプトを生成する

[references/notebooklm_prompt_template.md](references/notebooklm_prompt_template.md) のテンプレートに従って、以下を含むプロンプトを生成する:

- 分析メモ（コアメッセージ、入口の問い、主要ポイント、ユニークな示唆、未解決ギャップ）
- 確定スライド一覧（Slide 1〜最終番号まで全部。各スライドに要点・根拠・つなぎ）
- 出力指示（出力1: チャット欄、出力2: 読み原稿、出力3: スライドデック）
- カスタマイズ欄（聴衆、目的、発表時間、トーン、発表者）
- デザイン指定
- 20枚超えの場合は自動バッチ分割指示

確定スライド一覧のフォーマット:
```
Slide 1｜（スライドタイトル）
- 要点：（記事の該当箇所の内容）
- 根拠：（ソース名／該当箇所）
- つなぎ：（次スライドへの接続文。読み原稿用でスライドには表示しない）
```

### Step 5.5: ユーザーレビュー＆微修正

プロンプト生成後、確定スライド一覧をユーザーに提示してレビューを受ける。

提示フォーマット:
```
## スライド構成レビュー（全N枚）

1. Slide 1｜（タイトル） — 要点の1行要約
2. Slide 2｜（タイトル） — 要点の1行要約
...
N. Slide N｜（タイトル） — 要点の1行要約

修正したい箇所があれば指示してください:
- タイトル変更: 「Slide 3のタイトルを〇〇に」
- 順番入れ替え: 「Slide 5と6を入れ替えて」
- スライド追加: 「Slide 10の後に〇〇を追加」
- スライド削除: 「Slide 7は不要」
- 内容修正: 「Slide 4の要点に〇〇を追加」
- OKならそのまま「OK」と言ってください
```

ユーザーの修正指示に従って `notebooklm_slides_prompt.md` を直接編集する。複数回の修正にも対応する。ユーザーが「OK」と言ったらStep 6に進む。

### Step 6: スピーカーノートを生成する（オプション）

ユーザーが希望すれば、確定スライド一覧の「要点・根拠・つなぎ」をもとにスピーカーノート（読み原稿）を生成する。

- トーンはカスタマイズ欄の指定に従う
- 各スライド冒頭に【Slide X｜タイトル】を目印として記載
- 目標字数 = 発表時間 × 読み上げ速度（デフォルト300字/分）
- 保存先: `speaker_notes.md`

**冒頭の自己紹介ルール（厳守）**:
- 1 枚目スライドの読み原稿に**自己紹介・名乗り・挨拶を入れない**。「こんにちは、〇〇です」「私は△△と申します」のような前置きは禁止。
- 1 枚目はそのスライドの本文要点（テーマの提示・問題提起など、確定スライド一覧の Slide 1 の「要点」）から直接書き始める。
- 発表者名・あだ名・肩書（「○○部長」「○○先生」「○○代表」「○○CEO」など）を AI 側で**一切挿入しない**。SPEAKER 値が指定されていても、それを冒頭の名乗りに使うことはしない。
- カスタマイズ欄の `発表者` の値は、語り口や視点（誰の立場で話すか）の参考としてのみ扱い、原稿の表面に固有名詞として登場させない。
- トーン（フォーマル／カジュアル）はカスタマイズ欄の `トーン` に従う。

### Step 7: 出力

以下のファイルを生成してカレントディレクトリに保存する:

- `notebooklm_slides_prompt.md` — NotebookLMにコピペするプロンプト本体
- `speaker_notes.md` — スピーカーノート（Step 6で生成した場合）

ユーザーへの案内:

手動の場合:
1. NotebookLMを開く
2. 入力ソース（Note記事やスライド構成案）をソースとして追加
3. キャラクター画像があればソースに追加（なくてもOK）
4. 生成されたプロンプトをチャットに貼り付けて実行
5. 出力1（分析メモ）→ 出力2（読み原稿）→ 出力3（スライドデック）の順で自動実行される
6. 20枚超えの場合はバッチ2のプロンプトを続けて貼り付ける

MCP自動化の場合（このリポジトリの notebooklm MCP を導入済みの場合）:
1. `notebooklm-generate` スキルを実行すれば、MCP経由でノートブック作成 → ソースアップロード → スライド生成 → ダウンロード → スピーカーノート挿入 → バッチ結合まで一気通貫で自動実行される
2. このスキル（notebooklm-prepare）の出力ファイルがそのまま入力になる

## 注意事項

- スライドの内容は入力ソースに忠実に。AIの推測や一般論で補完しない
- 入力ソースの内容を省略・要約しない。1スライドも欠けさせない
- プロンプトの出力順序は「出力1→出力2→出力3」を厳守。チャットへの読み原稿出力は不要
