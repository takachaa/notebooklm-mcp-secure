# NotebookLM スライド生成プロンプトテンプレート

> 出典: RICOのAIラボ (@RicoProject) のスライド枚数限界突破プロンプトをベースに、読み原稿・デザイン指定・カスタマイズ機能を統合した完全版

## テンプレート本体

以下のテンプレートに、各Stepで確定した情報を埋め込んで出力する。

```
あなたはプレゼンテーションの専門家（構成作家・スピーチライター）です。
NotebookLMに読み込まれている「ソース（資料・議事録・記事・メモ等）」のみを根拠に、プレゼンの設計からスライド・読み原稿まで一括で作成してください。聴衆や目的は【カスタマイズ】欄の指定に従うこと。


【最重要ルール（根拠・正確性）】

根拠は「NotebookLMに読み込まれたソース」だけ。外部知識・一般論・推測で補完しない。
ソースに書かれていない固有名詞・数値・日付・断定は作らない。
必要情報がソース内にない場合は「ソース内で確認できない」と明記する。
重要な主張にはどのソースに基づくか根拠を添える（ソース名／章見出し／該当箇所の要約）。


【カスタマイズ】

聴衆：{{AUDIENCE}}
目的：{{PURPOSE}}
発表時間：{{DURATION}}
トーン：{{TONE}}
発表者の立場（任意）：{{SPEAKER}}
読み上げ速度（任意）：{{WPM}}字／分（未指定なら300字／分）
1枚あたりの目安（任意）：{{MPP}}分／枚（未指定なら1分／枚）
※目的が未記入ならソースから推定し、その旨明記する。


【スライドデザイン】

デザインスタイル：{{DESIGN_STYLE}}
配色（背景色／文字色／強調色／補助色）：{{COLOR_SCHEME}}
レイアウト方針：{{LAYOUT}}
その他の指定（任意）：{{DESIGN_EXTRAS}}


【時間調整ルール（必守）】

スライド枚数＝発表時間÷（分／枚）、±1枚まで調整可。
読み原稿の目標字数＝発表時間×（字／分）、±10%許容。
短時間→結論と意思決定材料優先。長時間→背景→根拠→論点→選択肢→推奨→次アクションの順に厚みを増す。


━━━━━━━━━━━━━━━━━━━━
A）分析メモ（ソース統合）
━━━━━━━━━━━━━━━━━━━━
1）コアメッセージ（1文）：プレゼンで一番伝えるべき結論。
2）入口の問い（冒頭30秒用）：聴衆が自分ごと化できる問いを2〜3案。
3）外せない主要ポイント（5〜7個）：重要な事実・示唆・判断材料＋根拠ソース。
4）ユニークな示唆（2〜4個）：一部ソースにしかないが差別化に効く示唆＋根拠。
5）未解決・ギャップ：答えきれていない問い、前提不足、追加確認すべき観点。


━━━━━━━━━━━━━━━━━━━━
B）プレゼン設計図
━━━━━━━━━━━━━━━━━━━━
各スライドについて以下を出力：
1）スライドタイトル　2）伝える要点（1〜2行＋根拠ソース）　3）想定所要時間　4）聴衆に残す一言

▼自己点検：時間配分が発表時間に収まるか確認。収まらなければ調整。

▼確定スライド一覧（マスター）：自己点検後、以下の形式で全スライドを列挙する。

{{SLIDE_LIST}}


━━━━━━━━━━━━━━━━━━━━━━━━━━━━
【出力指示】★Studio連携の核心★
━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■前提（必ず理解してから実行すること）
Studioのスライドデック機能・テーラードレポート機能はチャットの過去出力を参照できない。
user_steering_promptやdocument_directiveに書いた内容だけがStudioへの唯一の入力となる。
したがって、B）で作成した確定スライド一覧（マスター）の全文を、各パラメータ内に直接・完全に書き出すこと。
省略・要約・「上記参照」のような間接参照は絶対に禁止。1スライドも欠けてはならない。


■出力1：チャット欄
A）分析メモ
B）プレゼン設計図（末尾に確定スライド一覧）


■出力2：読み原稿（Studioテーラードレポート生成）
確定一覧完成後、続けて読み原稿を生成する。パラメータ：
report_type: テレプロンプター読み原稿
report_description: プレゼン発表用読み上げ原稿
language_code: ja
document_directive: 以下の構成で組み立てる

document_directiveの構成：
（1）冒頭に以下の指示文をそのまま書く：
「プレゼンのスピーチライターとして、以下の確定スライド一覧と原稿ルールに従いテレプロンプター用読み原稿を作成せよ。」
（2）続けて【原稿ルール】として以下をそのまま書く：
聴衆：【カスタマイズ】欄の聴衆をそのまま書き写す。
目的：【カスタマイズ】欄の目的をそのまま書き写す。
発表者の立場：【カスタマイズ】欄の発表者の立場をそのまま書き写す。
トーン：【カスタマイズ】欄のトーン指定をそのまま書き写す。
目標字数：発表時間×（字／分）で計算した値を書く（±10%許容）。
冒頭の自己紹介：1枚目に挨拶＋自己紹介を入れる場合、発表者名は【カスタマイズ】欄の「発表者の立場」の値をそのまま使う。発表者の立場が未指定または空のときは「〇〇」というプレースホルダを使い、固有名詞・肩書を勝手に補わない（例:「こんにちは、〇〇です。」）。「れん学長」など架空の固有名詞は絶対に挿入しない。
各スライド冒頭に【Slide X｜タイトル】と表記（読み上げない目印）。
タイトル・順番・枚数は一覧と完全一致（変更・省略・増減禁止）。
本文は一覧の「要点・根拠・つなぎ」だけを話し言葉に展開。新論点・事実の追加禁止。
連続テキスト、段落分け。箇条書き・注釈・演出指示は不可。
句読点は呼吸位置に適切に打つ。冒頭から本文開始、前置き水増し禁止。
（3）続けて【確定スライド一覧（マスター）】として全スライド分を書き写す。省略禁止。


■出力3：スライドデック（Studio生成）
読み原稿生成後、続けてスライドデックを生成する。パラメータ：
deck_type: presentation
length: dynamic
language_code: ja
user_steering_prompt: 以下の構成で組み立てる

user_steering_promptの構成：
（1）冒頭に以下の指示文をそのまま書く：
「以下の確定スライド一覧に厳密に従いスライドを作成せよ。一覧にないスライドの追加・削除・順序変更・内容改変は禁止。各スライドの要点を本文に、スライドタイトルをタイトルに使用。ただし「つなぎ」はスライドに含めないこと。つなぎは読み原稿専用の情報であり、スライド本文・タイトル・注釈のいずれにも表示しない。」
（2）続けて【デザイン指定】として【スライドデザイン】欄の内容をそのまま書き写す。
（3）続けて【確定スライド一覧（マスター）】として、出力2と同一の内容をそのまま再利用する。

※20枚超の場合は20枚ずつ分割して複数回生成。

出力1→出力2→出力3の順に実行すること。チャットへの読み原稿出力は不要。
```

## プレースホルダー一覧

### カスタマイズ
- `{{AUDIENCE}}` -- 聴衆（例: 非エンジニアだがAIを使って業務効率化したい方）
- `{{PURPOSE}}` -- 目的（例: 理解促進）
- `{{DURATION}}` -- 発表時間（例: 30分）
- `{{TONE}}` -- トーン（例: 落ち着いた親しみのある会話風）
- `{{SPEAKER}}` -- 発表者の立場（例: 「田中（マーケ部）」「個人YouTuberの〇〇」など）。**未指定の場合は読み原稿冒頭の自己紹介で「〇〇です」というプレースホルダを使う。AI が勝手に固有名詞や肩書を補ってはいけない。**
- `{{WPM}}` -- 読み上げ速度（デフォルト: 300字/分）
- `{{MPP}}` -- 1枚あたりの目安（デフォルト: 1分/枚）

### デザイン
- `{{DESIGN_STYLE}}` -- スタイル（例: 堅実でクリーンな企業スタイル）
- `{{COLOR_SCHEME}}` -- 配色（例: 背景#ffffff、文字#0ea5e9、強調#e9520e、補助#7dd3fc）
- `{{LAYOUT}}` -- レイアウト方針（例: グリッドベースの整然とした配置）
- `{{DESIGN_EXTRAS}}` -- その他指定（キャラクター画像、フォント非表示ルール等）

### コンテンツ
- `{{SLIDE_LIST}}` -- 確定スライド一覧（Slide 1〜最終番号まで全部）

## 確定スライド一覧のフォーマット

```
Slide 1｜（スライドタイトル）
- 要点：（記事の該当箇所の内容）
- 根拠：（ソース名／該当箇所）
- つなぎ：（次スライドへの接続文。読み原稿用で、スライドには表示しない）
```
